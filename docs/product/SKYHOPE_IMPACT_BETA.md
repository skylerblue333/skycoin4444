# SkyHope Impact Beta

SkyHope's canonical /charity route is an **engineering-beta service planning and personal evidence workspace**.

## What is implemented

- deterministic, bounded service-plan generation across five impact tracks;
- duration and team-size validation;
- role planning and evidence checklists;
- stable plan receipt IDs;
- device-local saved-plan journal;
- personal planned/completed status;
- direct navigation into HopeAI, SkySchool, Gaming, Social, and the ecosystem map;
- release tests that prevent the old fabricated charity claims from returning.

## Truth boundary

SkyHope does **not** currently execute donations, token transfers, custody, payouts, smart contracts, charity verification, volunteer certification, tax receipts, or real-world impact measurement.

The previous charity page contained fixture donor leaderboards, fabricated vote totals, named-partner verification claims, and on-chain/smart-contract language despite the server Charity router being deliberately unavailable. Those claims are removed from the canonical experience.

A future financial contribution path must not be enabled until a real provider and reconciliation flow exists with authorization, receipts, failure handling, security controls, compliance review where applicable, and evidence-backed integration tests.

## Integration path

- /charity — SkyHope planning + local evidence
- /hope-a-i — planning and question refinement
- /sky-school — learning/preparation
- /gaming — no-value practice experiences
- /activity-feed — persisted beta social sharing
- /platform-map — ecosystem navigation
