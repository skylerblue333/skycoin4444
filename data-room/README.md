# Data Room Evidence Boundary

The `data-room/` tree is retained for business, historical, planning, investor, legal, marketing, community, and related provenance. It is **not** a canonical engineering-beta runtime, build, test, security, deployment, compliance, financial, token, or release-evidence surface.

Current engineering claims must come from the default branch and the canonical engineering documents linked from the root `README.md`, together with exact-head/default-branch CI evidence. If a data-room document conflicts with current code, tests, `SECURITY.md`, `docs/ENGINEERING_BETA_LIMITATIONS.md`, `docs/ARCHITECTURE.md`, `docs/PRODUCT_CATALOG.md`, or newer release evidence, the current canonical source wins.

Do not interpret business plans, forecasts, legal/compliance planning, token/Web3 descriptions, investor material, screenshots, diagrams, or historical readiness summaries in this tree as proof of production deployment, live provider connectivity, payment/banking settlement, custody, chain execution, regulatory approval, audited security, durable persistence, or release readiness.

Historical material should be preserved when it has provenance value, but stale or duplicate readiness documents should be quarantined under an explicitly historical/archive path rather than presented beside current canonical release documentation.
